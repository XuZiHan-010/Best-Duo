# ADR-0003：候选评分不得读取真实隐藏牌

- 状态：Accepted
- 日期：2026-07-13

## 决策

Agent 候选决策分为三层：生成合法动作、排除从可见信息即可严格证明必输的动作、对剩余动作做高胜率排序。

- 动作合法性由规则层和服务端动作层确定。
- 硬剪枝只能使用 `DiscussionView` / `TurnView` 中可见的信息。
- 高胜率评估可对未知牌进行符合公开信息的采样，并在采样世界中复用完全信息求解器。
- 禁止把真实 `GameRoom` 的隐藏牌交给候选排序器，也禁止用真实隐藏牌生成看似无牌值的分数或 top-N。

## 理由

当前求解器是完全信息求解器，直接复用真实牌面会让 Agent 通过候选排名间接作弊；只按当前部分和强剪枝又可能错误删除仍可补救的动作。

## 后果

- `candidateGenerator` / `candidateEvaluator` 的公开输入必须是遮蔽视图，而不是 `GameRoom`。
- 第一版先做安全剪枝和启发式排序，信念采样作为后续增强。
- 若采样求解消耗明显 CPU，应放入 Worker Thread，避免阻塞 Socket.IO 事件循环。
