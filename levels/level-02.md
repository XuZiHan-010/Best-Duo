# 第 2 关 · 精打细算

- **关卡编号 (levelIndex)**: 2
- **难度**: ★★★
- **区段数**: 6（固定）
- **时钟中心值 (centerCap)**: ∞（`null`）—— 本关暂不设每区段上限；如需收紧难度可改为具体数字
- **牌堆 (deck)**: 全局牌库 24 张（白 1–12 + 黑 1–12），每局随机抽 12 张发牌 —— 本关含具体点数
- **设计意图**: 同时引入**单区段数值范围**与**区段牌数上限**两类约束，逼玩家在“点数”和“张数”之间权衡。

## 通关条件

人类可读：

- 区段 2 的**总和**必须在 **12–16 点**（含 12 和 16）之间。
- 区段 6 **最多只能放 3 张牌**。

结构化（区段编号 1–6）：

```json
[
  { "type": "sum-range", "segment": 2, "min": 12, "max": 16 },
  { "type": "max-cards", "segment": 6, "count": 3 }
]
```

## 备注

- “最后一个区间只能有 3 张牌”按**最多 3 张**（`max-cards`）理解；若本意是**恰好 3 张**，请改成 `{ "type": "exact-cards", "segment": 6, "count": 3 }`。
- 12–16 点的可行性取决于本局随机抽到的 12 张牌。系统**发牌前已做可解性校验**：抽到无解牌面会自动重抽，因此玩家拿到的牌一定存在让区段 2 落在 12–16 的方案（见 [rules.md](../rules.md)）。实测随机牌面下本关近乎 100% 可解。
- 可视需要叠加 `{ "type": "all-nonempty" }`（是否要求放满 6 区间）。
